# Adaptive RAG와 근거 판정

이 문서는 제공된 학습 매뉴얼에 설명된 PDF 기반 RAG 흐름을 정리합니다.

## 문서 처리

문서를 페이지별로 읽고, 청크마다 문서 ID·출처·페이지 정보를 붙입니다. 청크를 임베딩해 벡터 DB에 저장하면 질문에 관련된 내용을 검색할 수 있습니다. 검색 결과를 합칠 때 중복을 제거하고 출처 정보를 답변의 근거와 연결합니다.

## 노드별 역할

| 노드 | 역할 |
|---|---|
| doc_route | 질문에 맞는 문서 ID 선택 |
| analyze | 시도 횟수에 따른 검색 개수 결정 |
| rewrite | 재검색용 질문 표현 생성 |
| retrieve | 문서 범위 필터, 검색, 중복 제거, 컨텍스트 구성 |
| answer | 검색된 컨텍스트를 기반으로 답변 생성 |
| judge | 답변의 근거 여부와 다음 행동 판정 |
| bump | 재시도 횟수 증가 |
| finalize | 최종 결과와 실행 로그 정리 |

## 상태에 남기는 정보

- 질문과 질문 변형 목록
- 검색 대상으로 허용한 문서 ID
- 검색 개수와 재시도 횟수
- 검색된 문서, 컨텍스트와 생성 답변
- Judge의 행동·근거 여부·이유
- 실행 로그

이 정보를 공유 상태로 관리하면 노드별 입력과 결과를 확인할 수 있습니다.

## 판정과 분기

| 판정 | 다음 흐름 |
|---|---|
| final | 답변을 확정하고 종료 |
| re-retrieve | 검색 범위와 질문을 조정해 다시 검색 |
| re-answer | 현재 근거를 유지한 채 답변을 다시 생성 |

매뉴얼은 시도에 따라 검색 개수를 3 → 6 → 10으로 늘리는 설정을 설명합니다. 이는 해당 예제의 설정이며 모든 문서에 대한 최적값을 뜻하지 않습니다. 재시도 한도를 두어 종료 조건도 명시합니다.

## 근거 판정의 해석

Judge가 반환하는 grounded 값은 모델의 판정입니다. 그 값 하나를 외부 정답에 대한 정확도나 사실성 보장으로 해석하지 않고, 검색 자료·생성 답변·출처를 함께 살펴보는 구조로 이해합니다.
